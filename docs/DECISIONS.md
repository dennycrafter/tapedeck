# Decisions

This file records every deviation from SPEC.md and every choice the spec left open, one entry at a time (SPEC section 0, rule 2). Nothing in the app is invented silently: if a judgement call was made during the build, it is written down here.

Each entry lists the date, the ticket, the decision, and a one line reason for it, newest first. Entries are never edited after the fact; a later decision that replaces an earlier one is added as a new entry that names the entry it replaces.

- 2026-10-14 (T4 fix): Downloaded songs are handed to the player as blobs labelled `audio/x-m4a` (Apple's type for .m4a), not `audio/mp4`; Save to Files still builds an `audio/mp4` File as SPEC 8.10 says. Reason: a probe on GitHub's WebKit showed `audio/mp4` blobs failing with "not supported" on some machines while `audio/x-m4a` played every time.
- 2026-10-14 (T4 fix): The service worker no longer uses navigation preload. Reason: offline, a page sometimes opened with the previous page's content; pages are small and the network-first rule is enough.
- 2026-10-14 (T6): "Add to Apple Music" shows in the song menu until the song is flagged (ready, waiting or downloading songs; not failed ones). Flagging a ready song also resets its attempts to 0 when it goes back to `waiting`. Reason: SPEC 8.11 sends ready songs back to the queue; a reset counter keeps the retry ladder fair for this second pass.
- 2026-10-14 (T6): The setting lives at `PUT /api/settings/apple-music { on }` and the song action at `POST /api/tracks/:id/apple-music`. Reason: SPEC 8.11 names the behaviour, not the routes.
- 2026-10-14 (T4): The downloader puts the MP4 index (moov) before the audio in every song: `-movflags +faststart` when converting, and a lossless `ffmpeg -c copy -movflags +faststart` rewrite when a downloaded .m4a has it at the end (kept as is if ffmpeg is missing). The two committed test tones were rewritten the same way (same audio, boxes reordered). Reason: a downloaded copy played from the phone (SPEC 8.9) must read the index first; with it at the end WebKit sometimes never started the song.
- 2026-10-14 (T4): Every play of a downloaded song gets a fresh blob URL (the player no longer caches blob URLs), and the server stores a play sent twice with the same `playedAt` once. Reason: a retry after an audio error must not reuse the same link, and an offline play may be resent after a send that did arrive.
- 2026-10-14 (T4): The offline checks run against a second e2e server, a real production build (`web/e2e/prod-server.mjs`, built into `.next-e2e`, served over https on port 3102) on the same stand-ins. Reason: `next dev` does not run the service worker, and with the network off it will not start the app from cached files even when they are all cached; only a production build shows what the phone will really do.
- 2026-10-14 (T4): `TAPEDECK_TEST=1` now also turns on the local storage stand-in, skips setup mode and enables `/api/test/seed` in a production build. Reason: the e2e production server needs the stand-ins; `db.ts` and the session code already honored the switch in production, so it stays one switch. It is never set on Vercel.
- 2026-10-14 (T4): The service worker has its own caching rules instead of `@serwist/next`'s `defaultCache`: `/api/*` and audio are network only, pages network first, app files and fonts stale-while-revalidate, cover images kept. Reason: `defaultCache` caches `/api/*` responses (SPEC 8.9 says network only) and caches nothing in development.
- 2026-10-14 (T4): Page HTML is not precached, only app code, styles, icons, fonts and the `/~offline` page; pages are cached as you open them. Reason: every page is behind the password, and a page fetched while the service worker installs was stored as the login screen (the offline Home showed the password box).
- 2026-10-14 (T4): Offline plays are queued in a third IndexedDB store, `plays`, and sent with their real time (`playedAt`) when back online; the database is version 2 (the /test-audio page's database had only `audio`). Reason: SPEC 8.6 asks for an IndexedDB queue without naming the store.
- 2026-10-14 (T4): "Save to Files" uses the share sheet only on touch devices (`pointer: coarse`); on a PC it always downloads, even where the browser could share files. Reason: SPEC 8.10 says normal download on PC. When fetching the song takes too long for iPhone's tap-only share sheet, the app keeps the file and asks for one more tap.
- 2026-10-14 (T4): Playwright's Chromium projects launch with `--ignore-certificate-errors`, and every test except the offline ones blocks service workers. Reason: Chromium refuses a service worker served with the run's self-signed certificate, and Playwright can not route requests a service worker makes in WebKit.
- 2026-10-14 (T3 leftovers): Edit details cover choice is Keep / Remove / Paste URL; a pasted link must start with http:// or https:// and the dialog stays open with a message otherwise. Reason: SPEC 8.4 names the three options; the PATCH route already rejects other URLs, so the dialog says it before saving.
- 2026-10-14 (T3 leftovers): An AI reply with confidence 0.5 or more now supplies the title and artist even when it says `is_music = false`; that verdict only skips the cover lookup. Replaces the earlier behaviour where non-music replies were thrown away. Reason: SPEC 8.4 says `is_music = false` does not block adding and only skips the cover lookup.
- 2026-10-14 (T3 leftovers): A reply below 0.5 is discarded whole, its `is_music` included, so the song counts as music and the cover lookup runs. Reason: SPEC 8.4 says to keep the rule result; using half of a reply it does not trust would be inconsistent.
- 2026-10-14 (T3 leftovers): Restore original strips only " - Topic" and "VEVO" from the raw artist (no longer " Official"); a raw artist that is only "VEVO" is kept as is. Reason: SPEC 8.4 lists exactly those two suffixes for Restore.
- 2026-10-14 (T3 leftovers): Rule cleaner: featured names stop where a bracket began; loose words after a removed marketing bracket are dropped ("See You Again ft. Charlie Puth [Official Video] Furious 7 Soundtrack" gives "See You Again (feat. Charlie Puth)"); a later bracket or "ft. X" there is kept; a marketing bracket at the start ("[MV] IU - Blueming") is only cut out; a feat clause before a kept bracket moves to the end ("Shape of You (Live at the BRITs) (feat. Stormzy)"); kept brackets get one space before them ("GANGNAM STYLE (강남스타일)"). Reason: the SPEC rules did not cover text after a marketing bracket, and the old output put description text inside the feat.
- 2026-10-14 (T3 leftovers): Deezer covers use the CDN's 600x600 size (the `1000x1000-` part of `cover_xl` rewritten to `600x600-`) instead of `cover_xl` (1000) or `cover_big` (500). Reason: SPEC 8.5 wants a 600x600 cover from either source. Not checked live: the build machine can not reach Deezer's image CDN, so this is in the handoff to confirm after go live.
- 2026-10-14 (T2): The T2 playback checks (auto advance and Media Session, reload mid-song, 30 seconds counts a play) run on the `iphone` project only. Reason: Playwright's Chromium has no AAC decoder, so the m4a test tone never plays on `desktop` or `android`; the same rule already applied to the T1 play check.
- 2026-10-14 (T2): T2 e2e checks make seeded songs ready through the downloader API (upload-url, PUT the test tone, complete) instead of `--selftest`. Reason: `--selftest` claims from the shared queue and can pick up another test's waiting song (the race noted in the T3 spec); the API path touches only the seeded song and is the same upload the downloader does.
- 2026-10-14 (T2): Added the test-only route `/api/test/seed` (404 unless `TAPEDECK_TEST=1` and not a production build) to insert made-up songs and read raw database counts. Reason: the e2e app keeps its database in memory inside the server process, so tests can not write to it or count rows any other way.
- 2026-10-14 (T2): Albums whose `album_artist` is empty (hand-edited albums) group under the song's artist. Reason: Edit details clears `album_artist`, and without a fallback every hand-edited song would be its own nameless-artist album.
- 2026-10-14 (T2): Album, artist and playlist pages live at `/album?name=&artist=`, `/artist?name=` and `/playlist?id=`. Reason: album and artist names can contain `/`, `%` and `?`; search params round trip them exactly, path segments do not.
- 2026-10-14 (T2): The Search tab filters your own library as you type, with the YouTube search (SPEC 8.7, Enter or button only) below it. Reason: the SPEC puts Search in the nav but only defines the quota-limited YouTube search; local filtering is free and is what a library search tab is expected to do.
- 2026-10-14 (T2): Saira comes from the `@fontsource/saira` npm package, not Google Fonts. Reason: self-hosted fonts work offline (SPEC 8.9) and the T0 check forbids requests outside localhost.
- 2026-10-14 (T2): "Edit details" moved from a button on the player bar into the song "..." menu (SPEC 10 lists it there); the T3 e2e check now opens it from the song's menu. Reason: the full player bar has no room for a text button and the SPEC menu already owns the action.
- 2026-10-14 (T2): The Home "Recently added" list shows the 30 newest songs with a link to all songs. Reason: Home is a summary; Library > Songs is the full list.
- 2026-10-12 (fix before T2): Added a GitHub Actions check (`.github/workflows/ci.yml`) that runs tsc, eslint, Vitest, pytest and Playwright on all three projects for every PR and every push to main. Reason: the new build machine cannot download Playwright's WebKit, so the `iphone` project (which owns the T1 and T3 UI checks) only runs honestly on GitHub's machines; a PR merges only when this check is green.
- 2026-10-12 (fix before T2): `web/app/layout.tsx` types its props explicitly instead of using Next's generated global `LayoutProps<"/">`. Reason: that global only exists after `next typegen` or a build, so `tsc --noEmit` on a fresh clone failed with "Cannot find name 'LayoutProps'".

- 2026-10-10 (T0 test harness) — The agent pytest suite targets Python 3.12 semantics while the build sandbox runs Python 3.13.14: the downloader ships to the owner's Windows PC on Python 3.12 (SPEC 8.3), so tests are written to pass on both and version-specific behavior is handled in code rather than assumed by tests.
